# lstarbg.com → CSV скрейпър (LINK STAR / EKOPHONE BULGARIA)

Чете три категории от B2B портала lstarbg.com и записва продуктите в CSV във
формата, който ползваме:

```
brand;name;sku;ean;price_eur;price_vat_included;note
```

| Път | Категория |
|---|---|
| `496_567` | Оригинални кейсове |
| `496_569` | Оригинални зарядни и адаптери |
| `496_570` | Оригинални кабели |

## Как работи

От 21–22.10.2026 lstarbg.com е Next.js (преди беше OpenCart). Затова
скрейпърът вече не разчита на HTML класове, а чете данните, които сайтът
влага в страницата като `self.__next_f.push([1,"..."])` (RSC „flight“ поток):

1. Влиза на `/sign-in`. Там входът е Next.js server action – обикновена
   multipart форма с `email`, `password` и скрити полета `$ACTION_REF_1`,
   `$ACTION_1:0`, `$ACTION_1:1`, `$ACTION_KEY`. Скритите полета се взимат от
   самата страница при всяко влизане (сменят се при нов билд). Паролата идва
   само от env и никога не се логва. Успехът се проверява на `/account`:
   нелогнат клиент получава 307 към `/sign-in`, логнатият – 200.
2. Старите адреси на категориите още пренасочват (308):
   `index.php?route=product/category&path=496_567` →
   `/categories/originalni-aksesoari/originalni-keysove`. Скрейпърът взима
   новия адрес от пренасочването, вместо да го зашива в кода.
3. Минава страниците на категорията с `?page=N` (по 50 продукта) до
   обявения от сайта `resultCount`.
4. **Отваря продуктовата страница на всеки продукт** – оттам идват SKU на
   производителя (`mpn`), наличността, снимките и таблицата
   „Спецификации“. Ако в листинга няма цена, цената се взима оттам. Ако
   цена няма и там, в `note` пише „НЯМА ЦЕНА“.
5. Спира с грешка, ако сайтът заприлича на нелогнат (`pricesHidden: true`)
   или ако нито един продукт няма цена – вместо да запише непълни данни.

Пауза 700 ms между заявките, повторение само на GET при 429/5xx, спиране
при 401/403, 30 s таймаут на заявка – същата политика като Koff клиента.

### Цени и ДДС

Сайтът показва цените **без ДДС** (`vatCounterpart.shownBasis: "exclusive"`,
множител 1.2 = 20 %). Магазинът работи с цени с ДДС, затова скрейпърът
умножава по множителя на сайта на едно място (`priceWithVat` в `parse.ts`) и
записва в `price_eur` цената **с ДДС**. Ако някога сайтът започне да дава
цена с ДДС (`"inclusive"`), числото минава непроменено. Режимът се вижда в
`out/lstar-report.json` (`priceBasis`).

### Колоните

- **sku** – SKU на производителя (`mpn` от продуктовата страница). Новият
  сайт вече не публикува стария SKU (напр. `GUHMP18X6PWKSGTK`); полето
  `sku` в payload-а е вътрешният номер на варианта и **не** се записва.
  Ако `mpn` липсва, а `model` е буквено-цифров код, се ползва `model`.
- **ean** – само когато `model` е точно 13 цифри (сайтът няма отделно EAN
  поле). При грешна контролна цифра има бележка.
- **price_eur** – текущата цена с ДДС (промо цената, ако има).
- **price_vat_included** – `yes` по подразбиране: скрейпърът сам е превърнал
  цената в цена с ДДС.
- **note** – `id` (старият OpenCart `product_id`), категория, `вътрешен код
  NNNNNNN` (model от 5-8 цифри, обикновено 7), откъде е цената, „изчерпан“,
  „НЯМА ЦЕНА“.

### Идентичност на продуктите

`sourceKey` в магазина остава `lstar-sync:<старият product_id>`. Новият сайт
е запазил старите номера: `id` в листинга и `productId` в продуктовата
страница са старите OpenCart id-та (проверено: `product_id=36393` се
пренасочва към продукта, чийто payload е с `productId: 36393`). Затова не
се налага свързване по SKU/EAN и няма дублиране.

### Цени за CaseKing (`lstar-products-priced.csv`)

Същият CSV + `price_b2b_eur` и `price_b2c_eur`. Правилото е CASEKING
PRICING v2 от `../scraper/pricing.mjs` (един източник за всички
доставчици), **без** добавяне на ДДС: `price_eur` вече е цена с ДДС, затова
базата е самата цена на доставчика, а не ×1.23 като при Koff.

## Пускане

Само чете от lstarbg.com; не пипа кошница, Convex или магазина.

GitHub → Actions → „Scrape lstarbg.com (manual)“ → Run workflow. Нужни са
два GitHub Secret-а: `LSTAR_EMAIL` и `LSTAR_PASSWORD`. Резултатът е в
artifact-а на рън-а.

Локално:

```bash
cd koff-scraper/lstar
npm ci
LSTAR_EMAIL=... LSTAR_PASSWORD=... npm run scrape
```

Проверки преди merge/deploy:

```bash
npm run typecheck   # tsc
npm test            # vitest
```

`npm run build:browser` прави `dist/lstar-browser.js` – същият код за
тестов рън в браузър, в който вече си влязъл (HTML-ът се чете с вградения
DOMParser; `test/html-dom.test.ts` проверява, че дава същото като
node-html-parser).

## Към магазина (от 2026-10-19)

`npm run sync` праща продуктите в магазина (Convex `aware-toucan-771`) през
`convex/lstarSync.ts` в репото CaseKing. Пуска се в нощната задача „Sync to
case-king.bg“ веднага след Koff.

- **Ред за магазина** (`src/shop-row.ts`): категория по раздела на LStar
  (кейсове → `keysove-i-kalufi`, слушалки TWS → `headphones`, зарядни →
  `zaryadni-ustroystva` / `bezzhichni-zaryadni`, кабели →
  `kabeli-za-zaryadane`, HDMI → `drugi`); телефоните от „Модел Телефон“ +
  заглавието (първият е моделът, другите са `compat`); кейс без телефон се
  скрива, докато не му се зададе; име по схемата
  `[тип] [марка/серия] за [модел], [свойство] - [цвят]`; цени по живото
  правило без ДДС отгоре; „Наличен“ = 5 бр., иначе 0.
- **Дубликати**: бекендът взима името на Koff за същия код, взима EAN-а от
  ценовата листа на Koff по кода и слага реда в групата „най-евтиният наличен“
  (по EAN или по `sku:<код>`).
- **Безопасност**: DRY RUN по подразбиране; реален запис само с `LIVE=true`,
  а в нощната задача - само когато repository variable `LSTAR_SYNC_ENABLED`
  е `true`. Под 50 продукта спира; нулирането на наличност пази 90 %
  предпазителя. Отчетът е в `out/lstar-sync-report.json`.
